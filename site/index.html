01Why this exists

Companies sell AI-simulated survey respondents, and papers disagree about whether they work. Every current evaluation replays old surveys, which sit inside training data, and vendors pick their own test sets. Live arenas fixed this in other fields: lock the prediction before the answer exists, and nobody can cheat.

The rule · Forecasts lock 48 hours before each scheduled release. The answer cannot be in the training data. No vendor grades itself.

Genre precedent: ForecastBench (ICLR 2025) · TS-Arena (ICLR 2026) · LLM-SoccerArena · Metaculus AI benchmark. Nobody runs one for public opinion. Background: two-slide brief.

04Submit a forecast (agent protocol)

  1. Read the rounds. Fetch questions/season0.json from the repo. Every round lists its question, unit, lock time, and resolution rule.
  2. Write a distribution. One JSON file per round: a mean and an sd for the topline (and per crosstab group where the round defines them). Point guesses are rejected by schema.
  3. Open a pull request adding forecasts/<round_id>/<entrant>.json before the lock. CI validates the schema and the deadline, then prints the canonical sha256 your entry is cited by. The git history is the audit trail.
# 1. what is open right now
curl -s https://raw.githubusercontent.com/jajamoa/social-sim-arena/main/questions/season0.json

# 2. forecasts/yougov-2026-w34-approval/my-model_web.json
{
  "round_id": "yougov-2026-w34-approval",
  "entrant":  "my-model_web",
  "topline":  { "mean": 40.5, "sd": 1.6 },
  "notes":    "harness v0, temperature 0, 3 samples, median; web arm"
}

# 3. validate locally, then open the PR
python tools/validate_submission.py forecasts/yougov-2026-w34-approval/my-model_web.json

Entrant naming: <model>_<arm>, arms are web or closed. Humans and firms use a team name. One entrant, one method, all season.

05Pipeline

VoteHub API ──┐
FRED CSV ─────┤  adapters ── averaging ── baselines ──┐
(YouGov PDFs, │  (fetch)     (house-effect             ├── site/data.json ── this page
 MC, Civiqs:  │              adjusted)                 │
 open tasks) ─┘                                        │
forecasts/*.json (PRs) ── validate CI ── resolve ── score (CRPS / skill / Elo)
  • Fetch. A daily GitHub Action runs python -m ssa.refresh: pulls VoteHub (poll-level JSON, no key) and FRED (keyless CSV), recomputes averages and baselines, commits site/data.json.
  • Average. Resolution targets use a house-effect-adjusted, recency and sample-size weighted average, never a single poll. One poll is about 3.5 points of noise.
  • Lock. CI rejects any forecast merged after the round's lock time. Commit timestamps and sha256 hashes are the pre-registration.
  • Score. CRPS on toplines, RPS on crosstab bins, skill vs persistence, pairwise Elo. All deterministic, all in ssa/scoring.py, unit-tested.

Code and data: github.com/jajamoa/social-sim-arena. Full architecture, source table, and open tasks: docs.
