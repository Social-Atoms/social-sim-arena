# MTA daily ridership (data.ny.gov `sayj-mze2`)

**What the number is.** How many subway riders the MTA reports for one Monday-to-Sunday week, New York time: the sum of the seven daily `Subway` counts in the open dataset *MTA Daily Ridership and Traffic: Beginning 2020*. `Subway` includes the Staten Island Railway, per the dataset description; the separate `SIR` row is not added. A recent week is about 25 to 29 million riders. The rules are the approved Data Card [`mta-subway-weekly@v2`](../data-cards/mta-subway-weekly.json) (sha256 `20269fe1b4524a3133e614048a0baabf3b16b91becc3a89c7b79c4b61843f575`); the card's pilot and first scored rounds are proposed in [`mta-subway-weekly.rounds.json`](../data-cards/mta-subway-weekly.rounds.json), not in the season.

**Where it is published.** [data.ny.gov/d/sayj-mze2](https://data.ny.gov/d/sayj-mze2), Export > CSV, which is `https://data.ny.gov/api/views/sayj-mze2/rows.csv?accessType=DOWNLOAD`: one ~417 KB file, every day since 2020-03-01, header `Date,Mode,Count`. Rows post on business days only and trail by several days (the Friday 2026-11-06 posting reached Tuesday 11-03 for Subway, with Wednesday and Thursday present as empty rows). There is no release calendar, so SSA sets and resolves the metric (docs/sources.md §1.1). Use and manual download are allowed by the OPEN-NY Terms of Use; automated retrieval is unclear (the "Public Participation" bullet against scripts), so **no workflow fetches this file**. Inventory rights stay `unresolved` until maintainers decide; the card proposes `approved` for the manual route. Attribution: *Metropolitan Transportation Authority, MTA Daily Ridership and Traffic: Beginning 2020 (sayj-mze2), data.ny.gov, captured on the date in each file name, unmodified.*

**How the arena reads it: a person, every weekend.**

1. Between **Saturday 00:00 and Sunday 20:00 New York time**, open the dataset page in a browser and click Export > CSV. Note the time (UTC).
2. Run `PYTHONPATH=. python tools/ingest_mta_daily.py <the file> --downloaded-at <YYYY-MM-DDTHH:MM:SSZ>`. It refuses, and writes nothing, if the header is not `Date,Mode,Count`, if the time is outside the window, or if the newest posted Subway day is older than the Sunday six days before that Saturday ("Friday posting missing": wait for, or check, Friday's posting). A new Mode code is printed and recorded, and does not stop it.
3. `git add sources/mta_daily sources/manifest.json` and commit. The file lands as `sources/mta_daily/<download day, UTC>.csv`, write-once, with its time, URL, sha256, size, the newest posted day per mode and the window in `sources/mta_daily/fetches.json`.

If the Saturday download is missed or a target day is still empty, a download up to **Tuesday 12:00 ET** may be filed the same way; it can resolve the week that ended nine days earlier but is never a lock capture. Who: the track owner (yhtang@mit.edu) as primary; **a backup is to be named by maintainers**. Weekends that need covering this season include 2026-11-28 (first pilot lock), 2026-12-12, 12-19 (pilot verdict), 12-26 and 2027-01-02 (first scored lock). Two missed weekends in a row pause new rounds until a maintainer confirms the rota (`python -m ssa.adapters.mta_daily lapsed`).

**How a question resolves.** Forecasts lock Sunday 23:59 ET before the week. The ranked reference is the arena's `yoy4`, fixed from the weekend's download: R = Subway over the four weeks starting D-35 to D-14 / the same 28 days 364 days earlier, times last year's week D-364, with a spread equal to the root-mean-square error of the same rule over the 13 newest target weeks complete in that download. The week D-7 to D-1 is never used: it is not posted at the lock. If any reference day, year-earlier day or day of last year's week is empty, the round is cancelled. Persistence on the week D-14 is shown, unranked. The week resolves from the download taken Saturday D+12 to Sunday D+13 (six days after it ends), the same download that serves the next lock, or a resolution-only download up to Tuesday D+15 12:00 ET; none with all seven days posted by then and the round is cancelled.

**What to watch.** *The export URL is being retired*: on 2026-11-09 the CSV answered with `Deprecation` and `Sunset: Tue, 22 Dec 2026` headers pointing at [Socrata's notice](https://support.socrata.com/hc/en-us/articles/43491231777047). The portal's Export button should keep working; if the file then comes from another link, pass it with `--url` so the record says where it came from, and check the header is still `Date,Mode,Count` (the ingest refuses otherwise). *Late fill-in is measured by the pilot*: two unscored rounds (locks 11-29 and 12-06) and the 11-16 week's change between the 11-28 and 12-05 downloads decide, on 2026-12-19, whether six days is enough (`mta_daily.pilot_change`, under 0.5%). *Holidays*: the 364-day shift lines up Thanksgiving and most Monday holidays, not Christmas or New Year's Day, nor Labor Day 2026 or Memorial Day 2027; those weeks are flagged in the round text (`ssa/us_holidays.py`). *Storm days* fall to about a fifth of normal and are real behaviour, so there is no outage threshold. *Backtests use today's backfill*, not first prints.
